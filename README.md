Уязвимое веб-приложение на Python/Flask, скрипты
эксплуатации уязвимостей и патчи в формате `diff`.

## Часть 1. Приложение и уязвимости

Простое приложение «гостевой книги» с авторизацией. Реализованы две уязвимости
из OWASP Top 10:

| # | Уязвимость | Категория OWASP | Где |
|---|------------|-----------------|-----|
| 1 | **SQL Injection** | A03:2021 – Injection | форма входа `/login` |
| 2 | **Stored XSS** | A03:2021 – Injection (Cross-Site Scripting) | гостевая книга `/guestbook` |

### Почему это уязвимо

**SQL-инъекция.** Запрос к БД собирается конкатенацией строк, пользовательский
ввод попадает в SQL напрямую:

```python
query = "SELECT * FROM users WHERE username = '%s' AND password = '%s'" % (username, password)
```

Ввод `admin' -- ` в поле логина превращает остаток запроса в комментарий и
позволяет войти без пароля.

**Хранимый XSS.** Текст сообщения сохраняется в БД и затем вставляется в HTML
без экранирования (ручная сборка строки в обход автоэкранирования Jinja):

```python
html += "<div class='msg'>%s</div>" % message_text
```

Сообщение вида `<script>...</script>` выполнится в браузере каждого, кто
откроет страницу.

## Запуск приложения

```bash
cd app
python -m pip install -r requirements.txt
python app.py
```

Приложение поднимется на `http://127.0.0.1:5000`. При первом запуске рядом с
`app.py` создаётся файл базы данных SQLite `app/lab.db` и наполняется
начальными данными. При последующих запусках используется тот же файл (данные
сохраняются между перезапусками). Чтобы сбросить стенд в исходное состояние,
удалите `app/lab.db` — он пересоздастся при следующем старте. Файл БД добавлен
в `.gitignore` и в репозиторий не попадает.

Учётная запись для демонстрации: `admin` / `s3cr3t-admin-pw`.

## Часть 2. Эксплуатация


```bash
cd exploits
python -m pip install requests
python exploit_sqli.py     # вход в обход пароля + выгрузка таблицы users
python exploit_xss.py      # внедрение <script> в гостевую книгу
```

Каждый скрипт печатает, что он отправляет и что получает в ответ, чтобы было
видно факт эксплуатации.

## Часть 3. Патчи

Обе уязвимости исправляются одним патчем в формате unified diff. Применение:

```bash
# из корня репозитория
git apply patches/fix-vulnerabilities.diff
```

**Суть исправлений:**

- **SQLi** → параметризованные запросы (`cursor.execute(sql, (username, password))`).
  Пользовательский ввод больше не является частью текста SQL.
- **XSS** → экранирование вывода (`html.escape(...)`), данные выводятся как
  текст, а не как HTML/JS.

После применения патчей оба скрипта из `exploits/` перестают срабатывать:
логин-инъекция возвращает «неверный пароль», а `<script>` отображается как
обычный текст.
